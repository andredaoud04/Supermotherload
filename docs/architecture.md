# Implementation decisions

- **Engine:** Godot 4.6.3 / GDScript, per owner authorization. Compatibility renderer and non-threaded web template preserve browser support without SharedArrayBuffer requirements. Native export remains possible but has not been validated.
- **Terrain:** fixed-size cell arrays, not a node or network object per tile. Generation and saved edits are independent of rendering. Swept, substepped AABB collision is shared by rig, explorer, and creatures. Visible cells only are drawn. The prototype bounds the entire sector; chunk streaming is unnecessary at this scale.
- **Movement:** four-direction excavation with an articulated drill; assisted thrust in open space. Short acceleration and stronger braking preserve precise steering. Track animation uses physical travel; camera lead and impact shake can be disabled with reduced motion. Hull-clearance excavation removes the cells needed by the rectangular vehicle. Cargo-full rigs cannot destroy valuable ore without collecting it.
- **Modes:** title, expedition, colony. The colony is a separate simulation. Returning deposits cargo exactly once and repairs equipment. Departing preserves the excavated sector. On-foot boost prevents routine shaft traversal traps.
- **Combat:** manual directional rifle fire with modest line-of-sight aim assistance, swept projectiles, terrain blocking, three simple enemy behaviors, and capped cosmetic particles. No full-world destruction from ordinary bullets.
- **Progression:** ore-funded upgrades. Drill upgrades affect speed and cargo, workshop requires an on-foot discovery and affects weapon damage, quarters affect maximum health. The deep archive unlocks research after the workshop and quarters: 8 crystals plus 120 haul credits buy hull 150 and 2.1 seconds of boost. Discoveries persist through recovery; old saves default added flags to locked.
- **Persistence:** versioned state, terrain seed + edit map, surviving enemies, and actor state. Alternating checksummed saves tolerate one bad write. Browser localStorage writes are synchronous to avoid background/close racing a filesystem sync. Storage failure is shown rather than claiming success.
- **Input:** landscape keyboard/mouse and multi-touch. Input resets and solo simulation pauses on focus loss or portrait rotation. Survey and pause overlays cannot leave held controls active. Touch controls track finger ownership separately for motion, aim, and boost; explicit control preferences override automatic detection.
- **Survey:** a seven-cell ground scan around the active explorer reveals visited areas. The map preserves these cells, shows the actual current terrain, hides undiscovered landmarks, and pauses solo simulation. It has no effect on collision or generation.
- **Art/audio:** a 256×512 texture atlas is synthesized once, with visible-cell draw calls, three parallax layers, 28 ambient motes, detailed industrial structures and directional weapon effects. Bounded real PointLight2D nodes provide local lighting. Cached sound effects and quiet motor/cavern loops avoid generating new PCM every mining tick. This remains prototype production art.
- **Build:** pinned vendor downloads and SHA512 verification. Automated tests run before export. Linux Vercel and GitHub builds use the same Node script as local Windows builds.

## Networking boundary

The isolated WebSocket experiment now validates two native clients against server-owned mining and shared snapshots. It is excluded from the public web export. Godot's ENet UDP transport cannot be assumed to run in a browser. Our Vercel deployment currently serves static assets; Vercel now offers WebSocket Functions, but durable room routing and limited connection lifetimes require explicit design. See [current evidence and implementation boundaries](networking.md). Do not describe a locally passing transport experiment as implemented four-player co-op.

The intended authority owns terrain edits, damage, collection IDs, and progression commits. Clients consume sequenced edits and can request a full snapshot after gaps. A seed alone is insufficient to synchronize movement or damage. First validate two clients with drilling/collection/dismount, then four separate rigs and cameras before building matchmaking.
